# RAG 知识库与检索问答

## 需求说明

把学习笔记、项目文档和收藏资料整理成个人知识库，聊天时开启知识库后固定先查找个人资料，再结合查到的内容回答，并能打开回答对应的原文位置

例如上传项目说明后，提问“这个项目怎么启动”，回答应引用说明中的启动命令；以后订阅 RSS 后，提问“本周收藏的 Agent 文章有哪些观点”，能够按时间和来源查找自己的收藏

RAG 指“检索增强生成”：资料入库时提取文字、分段并建立索引；提问时检索相关片段，将片段与问题一起提供给聊天模型。上传图片让模型看图属于当前对话的输入，图片上传成功本身不会建立知识库索引

完整需求覆盖知识库管理、资料导入、后台处理、资料预览、检索问答、引用留存、更新删除，以及 RSS 等来源的接入。按文末顺序分阶段实现，第一阶段就需要完成从导入到问答的完整链路

## 知识库入口与管理

侧边栏增加“对话”和“知识库”入口，沿用现有中性色、深浅主题和简洁布局。切换页面时保留正在查看的会话和未发送草稿，知识库页面不影响后台正在进行的回答

知识库页面直接展示个人资料列表和上传入口。用户上传后系统自动解析、分段并建立索引，可检索的资料供开启知识库的会话使用，聊天时不需要选择具体资料范围

个人资料统一管理，页面显示资料数量、可检索数量与最近更新时间。文件、RSS 和网页通过来源类型、标题、时间等信息区分；这些信息用于查找和管理，不要求用户先建库、分类或指定资料范围

资料列表提供上传、查看、更新、删除和失败重试。解析参数、分段结果和索引信息放在详情中按需查看，不放到上传和聊天的必填流程里

所有数据沿用当前个人资料归属，资料、原文和检索均由后端核对所属用户；网页、Windows 和手机客户端共用同一套服务端记录

## 资料导入

文件导入支持 TXT、Markdown、PDF 和 DOCX。用户可以一次选择多个文件，每个文件独立展示上传和处理状态，单个失败不影响其他文件。建议首版产品限制为单文件 20 MB、每批最多 10 个，限制集中由后端提供，前端展示同一规则

TXT 和 Markdown 提取文本，保留标题、段落和代码块；普通 PDF 按页提取，保留页码；DOCX 按标题、段落和表格提取，不编造页码。Markdown 正文中的外部图片和链接先作为资料内容保留，上传时不自动下载远程资源

纯扫描 PDF、加密 PDF、损坏文件或提取后没有有效文字时，明确显示原因，例如“未检测到可提取文字，需要 OCR”或“文件已加密”。混合 PDF 允许索引实际提取到的文字，但需标记未能识别的页面，不能展示为整份文件已完整识别

文件校验结合扩展名、实际格式和解析结果。文本优先自动识别常见编码，无法可靠识别时给出提示，不能把乱码作为成功内容入库。界面支持预览提取结果，便于发现表格错位、乱码或内容缺失

个人资料中，相同文件内容通过内容指纹去重，返回已有资料及处理状态，不重复创建向量。普通上传遇到同名但不同内容时保存为独立资料，不额外弹出选择流程；用户在已有资料的“更新内容”操作中上传文件时，才替换该资料并建立新版本

聊天中的图片附件继续用于当前对话；需要长期检索的资料从知识库入口导入。两种用途可以共用文件存储能力，但不会因为聊天里发过文件就自动进入知识库

## 处理状态与资料详情

上传完成表示原文件已保存，只有索引完成后才表示“可检索”。后端记录持久化处理任务，刷新、离开页面或关闭客户端不会丢失任务

| 页面状态 | 含义与允许操作 |
|---|---|
| 上传中 | 文件尚未完整保存，显示上传状态，失败时可重新上传 |
| 待处理 | 原文件和任务已保存，等待后台领取 |
| 解析中 | 提取正文及页码、标题等位置，显示当前阶段 |
| 建立索引中 | 分段、调用 Embedding、写入向量，显示已处理片段数量 |
| 可检索 | 完整版本已生效，可以预览、检索、更新或删除 |
| 处理失败 | 显示失败阶段和中文原因，可以重试或删除 |
| 更新中 | 新版本处理中，已有成功版本继续可检索 |
| 更新失败 | 新版本失败，展示原因，旧版本继续可检索 |
| 删除中 / 清理失败 | 已停止参与检索，继续清理文件、分段与向量；失败可重试 |

处理进度优先展示真实阶段和已完成数量，不根据等待时间模拟百分比。首版允许在页面可见时轮询任务状态，离开后停止轮询；处理工作继续在后端执行

资料列表显示名称、来源类型、文件类型、处理状态、更新时间和片段数量，支持按名称搜索、按来源和状态筛选，并分页加载。需要单独区分文件字节数、提取文字量和分段数量

详情展示原文件信息、提取正文、分段预览、页码或标题位置、当前有效版本及最近处理结果。用户可以下载原文件、修改显示名称、重新处理、更新内容或删除；修改名称不重新生成向量

“重试”使用已保存的原资料，重新执行失败任务，不能产生重复的有效片段。“重新处理”按当前解析和分段设置建立新版本，即使原文件内容未变，也不能直接追加到旧索引

用户可查看任务失败是文件解析、模型认证、模型限流、模型超时还是向量存储失败。错误提示包含可操作信息，不包含密钥、数据库语句或完整上游响应

## 分段、索引与模型配置

提取后的内容按标题、段落和长度分段，相邻片段保留适量重叠，减少一句话或一个知识点被切断的问题。代码、列表和表格尽量保持完整；较长内容拆开后仍保留原章节和位置

每个片段可以追溯到所属用户、资料、内容版本和原文位置。PDF 至少保留页码，Markdown 保留标题路径，普通文本保留段落或字符范围。资料预览和回答引用使用同一套定位信息

Embedding 使用专门的向量模型，聊天模型仍负责回答。两者分别配置，切换 `qwen-plus` 和视觉聊天模型不会重新生成知识库向量

Embedding 服务需要可以替换，模型名、向量维度和版本信息与索引一起保存。替换 Embedding 模型、改变维度或不兼容的分段配置时，需要建立新索引；不能把新问题的向量直接放进旧模型的向量空间比较

新版本只有在所有必要片段完成并校验后才生效。部分写入、任务失败或服务中断都不能把半份资料标记为可检索。重建期间保留旧索引，成功后统一切换，随后清理旧版本

Milvus 保存用于相似度检索的向量及必要筛选信息，MySQL 保存资料信息、片段正文、版本和任务记录。原文件继续使用文件存储，当前可落本地，后续可替换成 OSS 等对象存储

## 检索与效果检查

知识库页面的搜索框支持直接查找个人资料，输入问题即可查看相关片段，不需要选择知识库，也不必先调用聊天模型。结果显示资料名、原文位置、片段内容和匹配顺序，点击进入对应资料详情

检索自动覆盖当前个人资料中已生效且未删除的内容，默认排除待处理、失败和仅部分写入的版本。资料名搜索与正文语义检索是两种操作，前者找文件，后者按意思找片段

查询文本使用与目标索引兼容的 Embedding 模型编码，再向 Milvus 召回候选片段。候选去重、相邻片段适度合并，按相关性和上下文预算选出最终内容，不能把整个知识库都拼进提示词

召回数量、片段大小、相似度筛选和上下文预算集中配置，不在多个模块重复写常量。匹配分数用于排序和调试，不向用户承诺“答案准确率为百分之多少”；不同距离计算方式和模型的原始分数不能直接混比

检索完成但没有相关资料、个人知识库尚无可检索资料、检索服务不可用，分别给出不同结果。找不到内容不等于系统出错，也不能因为搜到了几段文字就声称它们能支持答案

后续增加关键词与向量混合检索、重排序、按日期和来源筛选时，保持检索结果与引用结构稳定。第一阶段至少提供向量语义检索、个人资料归属过滤和重复片段处理

## 聊天中的知识库开关

输入框旁增加“知识库”开关，不需要选择具体知识库。新对话默认关闭，已有会话由服务端保存开关状态，刷新、换浏览器和客户端后沿用该会话的设置。

关闭时不检索个人资料，也不向模型提供知识库检索工具，按普通对话处理，现有联网搜索仍可使用。开启时每轮固定先执行知识库检索，再调用聊天模型，不依赖模型主动选择工具。涉及实时信息时，模型仍可以继续联网。

检索当前用户的所有有效资料。默认只用当前问题检索，不以文字长度判断是否追问。“你好”“谢谢”和带有完整主题的新问题不拼接旧话题。仅对“它有什么缺点”“那怎么缓解”“第二种方法呢”等明确指代上文或省略主题的追问补充最近用户问题，不把模型回答正文混入查询。连续追问最多向前取 3 条用户问题，遇到独立问题停止回溯；本轮问题优先保留，整个查询最多 400 字符。首版使用保守的中文规则识别明显追问，不额外调用模型改写，无法识别时仍按当前问题检索。不改写保存的用户问题，不把图片 Base64 放入检索词；聊天模型继续接收现有预算内的历史消息。含图片的问题仍支持图片理解，这不表示支持以图搜图。

有命中时向模型提供相关片段与编号，回答展示可打开的来源。没有命中时显示“未找到相关资料”，允许模型继续回答，不生成知识库引用。检索失败时明确显示原因，并告知模型本轮未获得资料，不能静默当作检索成功。用户要求只依据资料时，没有依据就明确说明。

生成准备阶段在短事务内读取并锁定本轮开关，回答期间不允许切换。切换接口只返回会话编号和开关字段，避免旧快照覆盖消息。开启或关闭只影响后续请求，历史回答的引用保持原样；已完成请求按编号重放时不重新检索，未完成请求重试使用当前会话开关。

流式页面先展示“正在检索知识库”，随后展示命中数量、空结果或错误，之后逐段显示回答。资料为空时也返回清晰的空结果，不阻止聊天；停止生成会取消仍在等待的检索或模型请求，不影响入库任务。

## 引用与历史记录

回答中的知识库依据使用 `[1]`、`[2]` 等编号，回答下方展示对应资料名和页码、章节或段落。点击来源打开资料详情并定位片段；PDF 同时提供原文件入口。联网来源单独展示，避免把网页链接与本地片段混在一起

后端根据实际检索并提供给模型的片段生成来源清单，模型只引用本轮可用编号。未知或越界编号不能变成可点击来源。来源表示“这段资料被提供为回答依据”，不宣称系统已经自动证明每一句回答都正确

同一资料不同位置允许分别引用，同一片段重复引用只展示一份。资料之间存在冲突时尽量标明出处和时间，不能无依据地认定最新上传的一份一定正确

成功回答同时保存实际聊天模型、本轮实际使用的检索来源，以及对应的资料版本、片段位置和短摘录。刷新、切换模型和重复请求重放都展示当时的来源，不重新检索或重新生成

资料更新后，旧回答仍对应旧版本的引用快照，打开时标注“资料已有新版本”。旧版本原文已清理时展示保存的短摘录，并提示当前原文已更新；不能把旧引用直接跳转到新文档中的同一页冒充原依据

资料删除后，后续检索立即排除它，历史来源显示“资料已删除”，原文件入口失效。已保存回答和引用短摘录作为会话历史保留，用户删除会话时一并删除这些记录

已完成请求按原 `request_id` 重放保存结果，即使个人资料内容发生变化也不重新查询。失败或停止的请求尚无完整保存结果，重试时按当前会话模型重新执行，按当前会话知识库开关决定是否先检索，界面展示本次实际使用的模型与来源

## 更新、删除与后台任务

资料更新分为修改显示信息、替换内容和重建索引。修改名称不影响片段与向量；替换内容或重新处理创建新版本；模型迁移可以批量重建个人资料索引，并展示各资料进度

任务记录包括资料、目标版本、处理阶段、尝试次数、开始与结束时间和最后错误。后端有并发上限，避免批量上传把模型请求和内存全部占满；限流和临时网络错误可有限重试，格式错误、认证失败等需要用户处理的错误直接提示

同一资料同一版本同时只允许一个有效处理任务。进程重启后可以识别未完成任务并恢复或重新排队，过期执行器的迟到结果不能覆盖新版本。用户重复点击重试不会创建多个有效版本

删除资料先在 MySQL 标记不可检索，再异步清理所有版本的向量、正文与原文件。检索结果返回和回答定稿前均过滤已删除资料，避免 Milvus 清理延迟导致新回答重新带回已删除内容；正在回答中遇到这种变化时，取消本轮并提示重新提问，已经发送到客户端的临时文字不再保存

删除不允许后台解析任务再次把资料改回可检索。清理任务必须知道该资料涉及哪些旧索引，即使某个 Milvus 集合暂时不可用，也能保留待清理记录，恢复后继续执行

## RSS、网页与多模态扩展

文件上传是第一个来源入口，资料内部统一记录来源类型、来源标识、原始位置和采集时间。来源读取与解析、分段、Embedding、索引分别处理，后续加一种来源不重写聊天和检索

RSS 阶段支持添加、修改、暂停、删除订阅，填写订阅地址后自动采集到个人资料中，系统按默认策略同步；用户可手动同步并查看最近结果，需要时在订阅详情调整频率。暂停只停止后续采集，已经入库的文章继续保留；删除订阅时明确选择保留文章或连同文章删除

RSS 条目优先使用稳定的条目标识或规范化链接去重，标题变化不应创建重复文章。相同条目内容变化时建立新版本，无变化时跳过。保存作者、发布时间、订阅来源和原始链接；条目只有摘要时标为摘要，不声称已经读取全文。全文抓取失败时保留状态和失败原因，可以重试

网页阶段支持提交文章链接并提取正文，记录原始 URL 和抓取时间，手动刷新时建立新版本。仅导入用户明确提交的页面，抓取失败或页面要求登录时说明原因。手动粘贴文字也可以形成资料，走同一套版本与索引流程

后续 OCR 将扫描 PDF 和图片转成可检索文字，记录文字来自识别结果。图片风格相似检索则需要图片 Embedding 和对应索引，保留原图及位置；不能把目前的文字向量索引直接当成图片风格索引。音视频可以先转录文字，再复用文本检索，同时保留时间戳

来源、文件存储、解析器、Embedding 和向量存储均提供替换入口。只有新增能力实际实现后才在页面开放，不提前展示不能使用的按钮或要求用户填写未来功能的配置

## 技术方案

### 模块与数据

继续使用 FastAPI、LangGraph、MySQL 和 Milvus。API 包只接收参数与返回结果，知识库业务放在 `services`，文件和 RSS 等读取逻辑放在 `sources`，解析、分段、Embedding 与检索实现放在职责清晰的子包。优先复用现有 `Document`、`SourceAdapter` 与 `Retriever` 思路，按实际参数补充个人资料归属和定位信息，不把所有逻辑塞入协议文件

MySQL 建议增加 `cq_knowledge_document`、`cq_knowledge_version`、`cq_knowledge_chunk` 和 `cq_knowledge_job`，分别管理资料、版本、片段和任务，直接关联现有个人资料。消息关联结构化来源快照；具体字段和索引在实现前按查询与更新逻辑细化。当前单一个人知识库不单独建库管理表，会话不增加选库字段或问答模式字段

资料与索引采用独立版本号。Milvus 记录用户、资料、版本和片段编号及向量，MySQL 是有效版本和删除状态的最终依据。文件存储通过存储编号定位，原文件不放入 MySQL 或向量字段；当前可保存到项目 `data/knowledge/`，文件操作集中处理，便于以后迁移 OSS

Embedding 首个适配器使用百炼兼容服务，密钥可以复用现有后端配置，但模型、服务地址和维度独立配置。读取配置和创建客户端不能触发批量重建，缺少必要配置时在知识库页面提示，普通聊天继续可用

物理向量集合按 Embedding 模型、维度和索引版本组织，通过用户字段过滤个人资料。不同模型生成的向量不混入一个不兼容集合。索引迁移与兼容性由后端管理，不要求用户在聊天时选择集合或 Embedding 模型；当前使用统一的生效索引配置，迁移完成后再发布新配置

### 入库与检索执行

```text
文件 / RSS / 网页 / 手动文字
              ↓
保存原资料和来源 → 持久化处理任务
              ↓
提取正文与位置 → 分段 → Embedding → 写入待生效索引
              ↓
核对任务与资料状态 → 发布完整版本 → 清理旧版本
```

首版任务可由独立 Python worker 领取 MySQL 中的持久化任务，用短事务领取、租约和心跳避免重复执行。CPU 密集解析放到可超时终止的工作进程，文件与网络等待异步处理，任务执行期间不长期持有数据库连接。FastAPI 请求只负责保存并提交任务，不依靠进程内 `BackgroundTasks` 作为唯一任务记录

MySQL 和 Milvus 之间没有跨库事务，先用目标版本和稳定片段编号写入待生效数据，再核对片段数量与资料状态，最后在 MySQL 发布版本；重复写入可覆盖相同目标编号，失败版本不参与检索。删除与旧版本清理由持久化任务补偿，不能把两边写入当作一次数据库提交

```text
用户直接提问 → 读取本轮会话开关
                    ├─ 关闭 → model → 可选 web_search → 回答
                    └─ 开启 → retrieve → model → 可选 web_search → 回答及引用
```

LangGraph 使用固定的 `retrieve` 节点，入口按本轮 `knowledge_enabled` 配置选择路径。检索查询准备和实际检索分为相邻节点，让 SSE 可以在等待向量服务之前发出开始事件。检索结果保存在本轮图状态，模型通过单独的系统参考消息读取片段，资料正文中的指令不能改变工具权限。

运行配置包含当前用户、知识服务和本轮开关，按模型缓存的图不保存会话开关或引用。关闭时不调用知识库摘要、Embedding 或 Milvus。`knowledge_search` 不再注册到聊天模型工具列表，避免绕过开关；联网工具仍使用已有的 `@tool` 格式。

会话表补充 `knowledge_enabled` 布尔字段，默认 false，启动时为旧库补列。创建接口保存初始值，切换接口和生成领取共用会话行锁。引用元数据与问答整轮保存，JSON 返回与流式完成事件使用同一份结果。

### 接口变动

以下是本需求涉及的接口，前端仍通过 `/api` 代理调用。列表接口统一支持游标分页，检索与任务参数由后端校验，不一次返回全部正文和向量

| 接口 | 请求与结果 |
|---|---|
| `POST /conversations` | 新增可选 `knowledge_enabled`，默认 false，保存首次发送前的开关选择 |
| `PATCH /conversations/{id}/knowledge` | 请求 `{"knowledge_enabled":true}`，只返回 `id` 和 `knowledge_enabled`；生成中返回 409 |
| `GET /conversations`、`GET /conversations/{id}` | 会话信息增加 `knowledge_enabled`，用于恢复开关 |
| `GET /knowledge` | 返回个人知识库摘要，包括资料数量、可检索数量和处理状态，不需要前端提供知识库编号 |
| `GET /knowledge/documents` | 按名称、状态、来源筛选个人资料，支持分页 |
| `POST /knowledge/documents` | multipart 字段 `file`，保存文件并自动创建任务，HTTP 202；重复内容返回已有资料及状态 |
| `GET /knowledge/documents/{id}` | 返回资料信息、有效版本、处理结果和可用操作 |
| `PATCH /knowledge/documents/{id}` | 修改显示名称等不影响内容的信息 |
| `GET /knowledge/documents/{id}/content` | 分页读取提取正文和定位信息，可定位当前或仍保留的指定版本 |
| `GET /knowledge/documents/{id}/chunks` | 分页读取分段预览，不返回完整向量 |
| `GET /knowledge/documents/{id}/file` | 读取当前资料原文件，由后端核对归属和删除状态 |
| `POST /knowledge/documents/{id}/versions` | 上传替换文件并创建新版本，HTTP 202，旧版继续可用 |
| `POST /knowledge/documents/{id}/reprocess` | 使用已保存内容重试或重建索引，返回任务，HTTP 202 |
| `DELETE /knowledge/documents/{id}` | 先标记不可检索，再返回清理任务，HTTP 202 |
| `GET /knowledge/jobs/{id}` | 返回任务阶段、完成数量、失败原因和可重试状态 |
| `POST /knowledge/retrieve` | 接收查询词和可选筛选条件，在当前用户有效资料中检索，返回有序片段与来源；聊天调用时无需用户填写范围 |

两个消息发送接口的结果中，助手消息增加结构化 `citations`，包含本地引用编号、资料编号、版本、位置、显示名称和短摘录；历史普通消息返回空数组

流式消息接口增加 `retrieval_start`、`retrieval_end`，都携带原 `request_id`。开始事件说明正在查询个人资料；结束事件包含检索结果状态、命中数量和必要错误信息。引用通过新增 `citations` 事件和最终 `done.messages` 返回，正文仍使用 `delta`；来源打开时由后端查询资料是否仍存在，不把生成时的存活状态当成永久有效

RSS 阶段再增加订阅接口：`GET /knowledge/subscriptions`、`POST /knowledge/subscriptions`、`PATCH /knowledge/subscriptions/{id}`、`DELETE /knowledge/subscriptions/{id}` 和 `POST /knowledge/subscriptions/{id}/sync`。添加订阅只需提供地址，系统使用默认同步策略，也允许在详情修改频率；同步返回可查询任务；删除时明确是否同时删除已导入资料

网页和手动文字阶段分别增加 `POST /knowledge/webpages` 与 `POST /knowledge/notes`，统一返回资料与处理任务，后续管理复用已有资料接口

### 日志与实施顺序

日志延续中文输出与请求编号，记录资料、版本、任务、阶段耗时、分段数量、Embedding 批次数、检索命中数量和实际模型。入库任务离开 HTTP 请求后仍可通过任务编号关联上传记录。日志不打印原文全文、向量数组、文件内容或密钥

第一阶段完成知识库页面、TXT / Markdown 导入、持久化任务、分段、Embedding、Milvus、资料搜索、会话开关控制的固定检索、引用保存，以及更新和删除。这是第一版可实际使用的 RAG，不能以“文件已上传”作为整个需求完成

第二阶段补齐 PDF / DOCX 的解析与位置预览、图片消息的检索意图提取和索引模型迁移，使本地文件资料的管理和问答完整可用

第三阶段接 RSS、网页和手动文字，补齐周期同步、正文抓取、去重和内容更新；再根据真实资料扩展 OCR、混合检索、重排序、图片相似检索或音视频转录，每项沿用统一的资料、版本、任务和引用规则
