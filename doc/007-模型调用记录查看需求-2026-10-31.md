# 模型调用记录查看

## 需求

每条助手回复旁增加“查看调用”，打开右侧抽屉查看这次提问的知识检索结果和实际发送给模型的内容，默认折叠长内容，保持聊天页面简洁。生成中、失败和停止后的临时回复也提供入口，旧消息没有记录时明确提示，不根据历史聊天拼凑请求

知识检索展示实际查询词、耗时、失败原因和最终传给模型的资料片段，包括资料名称、版本、片段编号和完整引用文字。终端打印查询词、命中数量和每段前 200 字，完整内容以调用记录为准

模型请求按实际调用顺序分别展示，包含系统提示词、历史消息、本轮问题、知识库参考消息、工具定义、工具执行结果和实际发送的其他参数。提供请求 JSON 查看、复制与下载，记录来自 SDK 最终组装的 HTTP 请求体，不补造没有发送的默认参数

同一问题重试可能执行多次，每次执行独立记录，界面可分别展开；已成功问答的网络重放不新增记录。请求发出前保存参数，超时、模型报错和用户停止仍能查看已发生的调用。记录生成中、完成、失败、停止状态；应用意外退出时保留最后状态，过期未结束的记录显示为中断

图片沿用现有附件，数据库只保存附件引用及校验摘要。页面直接预览图片，普通 JSON 视图标明图片地址为存储引用；复制、下载完整请求时恢复实际发送的 Base64。文件缺失或内容变化时明确提示，不能把不完整数据冒充原始请求。API Key、鉴权请求头和含鉴权的服务地址不进入记录

记录保存于 MySQL，刷新或切换客户端仍可查询，删除会话时一并删除记录。记录操作使用独立短事务，不在等待模型期间占用数据库连接；记录失败只警告，不影响正常问答，页面能识别未捕获请求等不完整状态

## 技术方案

新增 `cq_ai_trace` 保存一次执行的会话编号、消息请求编号、HTTP 请求编号、模型、知识库开关、状态、检索快照和起止时间；新增 `cq_ai_call` 保存该执行内每次模型调用的顺序、请求体、图片引用、状态、耗时、HTTP 状态和安全错误说明。执行编号独立于消息请求编号，失败重试保留历史执行。外键关联会话而非成功消息，因此失败时不丢记录，删除会话自动级联清理

`app/services/traces.py` 负责执行上下文、记录写入和归属查询，`app/db/traces.py` 定义表，`app/schemas/traces.py` 定义响应结构，`app/api/traces.py` 只放路由。使用 ContextVar 在异步调用链中绑定本次执行，模型节点开始/结束时记录调用状态，httpx 请求钩子在发送对话请求前保存最终 JSON。上下文在请求结束时恢复，共享模型客户端不会混入其他会话的数据，Embedding 和网页搜索的 HTTP 请求不作为模型对话记录

流式和普通会话发送都启用记录。检索节点把实际传给模型的 retrieval 数据保存为快照，模型调用无论是否选择工具都分别记录。流式取消在受保护的清理阶段更新状态，写入设置短超时；进程崩溃遗留的运行记录按本次生成期限判断为中断。无会话的 `/chat` 调试入口沿用现有行为

图片构造消息时同步建立内容摘要到附件资料的映射，记录请求时用附件地址替换 Base64，其他消息和参数不截断。导出时按当前个人资料校验附件归属、读取文件并核对摘要，再恢复数据地址；文件处理放在工作线程

新增 `GET /conversations/{conversation_id}/requests/{request_id}/trace`，返回该请求的执行列表及各次检索、模型调用；没有记录返回空列表，未归属当前个人资料的会话返回 404。新增 `GET /conversations/{conversation_id}/requests/{request_id}/trace/calls/{call_id}/request` 返回恢复图片后的完整模型请求 JSON，附件不可恢复或请求未捕获时返回明确错误

前端新增独立 TraceDrawer 组件与请求类型，点击查看才请求详情。运行中的记录通过手动刷新查看最新状态，不后台持续轮询；抽屉关闭、切换会话时取消读取，忽略旧请求结果。抽屉支持加载、空记录、错误和重试、Escape 关闭、键盘焦点约束及窄屏显示
