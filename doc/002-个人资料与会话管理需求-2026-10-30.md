# 个人资料与会话管理

## 需求与逻辑

当前页面没有个人资料，历史会话只保存在浏览器中，模型每次只能收到最新的一条问题。本次将个人资料和会话记录保存到 MySQL，让页面刷新后仍能显示用户信息和历史对话，并让模型能够继续当前会话的上下文。

第一次访问时，系统自动生成一个带随机后缀的默认昵称，例如 `CQ用户-7F3A2B`，直接进入聊天页面。昵称显示在侧栏底部，用户可以从个人资料入口修改。昵称由后端生成并保存，前端只读取后端返回的结果，避免出现两份默认昵称。

会话列表从 MySQL 读取，按最近更新时间排列。发送第一条消息时创建会话，后端取问题去掉首尾空格后的前 28 个字符作为标题，与会话一起保存到 MySQL。前端直接显示返回的标题，即使首次模型调用失败，刷新后也能保留。回答成功时只保存问答和更新生成状态、时间，不再生成或覆盖标题。用户可以新建、切换、搜索、重命名和删除会话。侧栏会话旁提供修改标题按钮，原位输入后按回车或点击确认保存，Esc 或取消按钮放弃修改。标题去掉首尾空格后为 1–120 个字符，保存失败时保留输入供重试；生成回答期间暂不能修改标题。修改后的标题保存到 MySQL，刷新和后续问答都保留。页面刷新或更换浏览器后，仍可以读取已经保存的个人资料和会话。

刷新页面后恢复当前打开的会话，继续显示其消息、标题和模型，不创建新会话。点击“新对话”后回到空白聊天页，刷新仍保留空白页，发送第一条问题时才创建记录。会话已删除或不可访问时回到空白页；网络加载失败时保留当前会话位置，重试后继续恢复。

会话数据由服务端统一保存，各端分别记录自己正在查看的会话。电脑、手机或不同窗口可以打开不同会话，互不覆盖。

每个会话保存自己的模型。创建会话时使用当时的默认模型；之后即使系统默认模型发生变化，已有会话仍显示并继续使用原来的模型。每条模型回答同时记录实际使用的模型，方便查看历史和后续增加会话级模型切换。

每次发送消息时，服务端读取当前会话最近的历史消息，并和本次问题一起交给 LangGraph。模型最多接收最近 20 轮、约 6 万字符的上下文。模型成功返回后，将用户问题和模型回答作为一轮完整记录保存。

同一会话正在生成回答时，暂时不能继续发送，其他会话不受影响。模型调用失败时不保存半轮消息，页面提供重试。每次请求带有唯一编号，网络重试不会重复保存相同问答。删除会话时同时删除其中的消息。

## 技术方案

网页地址通过 `?conversation=会话ID` 记录当前页面位置，切换会话时更新，刷新后从已有会话列表恢复消息和模型，无须额外请求详情。列表读取成功后校验编号，无效时清除；读取失败时保留地址供重试。恢复期间显示加载状态，完成前不允许发送，避免误创建会话。点击“新对话”或删除当前会话时清除地址中的编号。

当前会话位置属于客户端导航状态，不在个人资料上设置所有设备共用的“当前会话”。后续 Windows 客户端或手机端以同一个会话 ID 调用接口，并使用各自的导航和本地持久化方式恢复页面。URL 中的编号仅用于定位，访问权限由服务端负责校验。

后端使用 FastAPI、LangGraph 和 SQLAlchemy 异步访问 MySQL，新增个人资料、会话和消息三张表，表名使用 `cq_` 前缀。应用启动时自动创建缺失的表。

个人资料表保存固定编号、昵称和创建时间。第一次读取资料时，由后端生成随机默认昵称并写入 MySQL；之后直接读取已有记录。会话表保存所属个人资料、标题、模型名、创建时间、更新时间和生成占用信息。消息表保存会话编号、顺序、请求编号、角色、正文和实际使用的模型名。

接口包括：

- `GET /profile`：读取个人资料，第一次访问时自动生成默认昵称。
- `PUT /profile`：修改昵称。
- `GET /conversations`：读取会话列表和已保存消息。
- `POST /conversations`：传入 `{"first_message": "首次问题"}`，创建会话并保存初始标题，不调用模型或保存消息正文。
- `GET /conversations/{id}`：读取一段会话。
- `PATCH /conversations/{id}`：修改会话标题，校验归属、标题长度和生成状态，更新最近修改时间。
- `DELETE /conversations/{id}`：删除会话及消息。
- `POST /conversations/{id}/messages`：按照会话绑定的模型发送问题并保存完整问答。

`GET /models/default` 返回新会话使用的默认模型；会话列表和详情通过 `model_name` 返回各自的模型。欢迎页显示默认模型，打开会话后显示该会话的模型。

创建会话时将默认模型写入 `cq_conversation.model_name`。发送消息时，后端根据会话的 `model_name` 创建或复用对应的 LangGraph 和模型客户端，同一服务的不同模型继续共用服务地址和密钥。修改默认模型只影响之后创建的会话。模型不可用时返回错误供用户重试，保持原会话的模型设置。

已有会话通过补充字段迁移：优先使用该会话最近一条带模型信息的回答回填；没有模型记录的旧会话使用迁移时的默认模型。已绑定模型的会话保持原值。

发送消息时，服务端先用 MySQL 行锁为会话设置生成占用，然后在事务外调用模型，成功后再次加锁保存结果并释放占用。占用带有过期时间，服务异常中断后可以恢复；旧请求完成时会检查占用编号，不能覆盖后续请求的结果。

页面打开后立即显示聊天主界面，个人资料在后台加载，完成后读取会话列表。资料加载期间侧栏显示“读取资料…”，连接失败时在主界面内提示并提供重试，输入框仍可编辑，待连接成功后再发送。重试成功时继续使用当前页面和已输入的内容。侧栏显示昵称和会话历史。主题、侧栏宽度等界面偏好继续保存在浏览器；会话正文和模型上下文以 MySQL 为准。接口层只处理 HTTP 参数和响应，数据库依赖放在 `app/dependencies.py`，个人资料和会话逻辑放在 `app/services/`，表模型和连接放在 `app/db/`。
