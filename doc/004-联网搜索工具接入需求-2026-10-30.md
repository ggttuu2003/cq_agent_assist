# 联网搜索工具接入

## 需求与逻辑

聊天遇到最新资讯或需要外部资料的问题时，由模型决定是否搜索。普通知识问答仍可直接回答。例如“介绍 Python 异步”可以直接回答，“最近有哪些 AI 新闻”则先搜索，再结合结果整理答案

个人使用默认采用 DDGS，不需要搜索 Key；同时保留 Tavily，按配置切换。搜索能力和具体服务分开，聊天流程、工具名称和前端展示保持一致。选择 Tavily 但没有配置 Key 时，普通聊天仍可使用，模型需要明确说明当前无法联网，不能假装已经搜索。DDGS 遇到网络问题或搜索源限制时如实提示，不自动切换到付费服务

搜索过程中显示“正在搜索网页”和查询词，结束后显示成功、没有结果或失败。最终回答附上真实搜索结果的来源链接，来源随回答一起保存，刷新后仍可打开。搜索失败时将明确错误交回模型，由模型说明情况，不把失败说成搜索成功

搜索和模型生成沿用同一轮会话的停止、超时和重试逻辑。停止会取消正在等待的搜索请求。完整回答成功后才保存本轮问答；已保存请求重试时重放原结果，不重新搜索。同一轮最多进行三轮工具调用，达到上限后要求模型根据已有信息作答，避免反复搜索

## 技术方案

### 搜索服务与图流程

搜索工具使用 `@tool(parse_docstring=True, response_format="content_and_artifact")`。函数文档通过 `Args:` 编写中文参数说明，由 LangChain 自动生成模型可见的参数定义；`Returns:` 说明文本结果和结构化来源两个返回值。查询词通过 `Annotated` 附加去除首尾空格和 1～400 字符的校验规则，不再单独维护参数模型。

`app/search/` 统一定义搜索输入和结果：输入为查询词，结果包含标题、链接和摘要。`ddgs.py` 和 `tavily.py` 分别调用对应服务并转成统一结果，`factory.py` 根据 `SEARCH_PROVIDER` 选择。当前支持 `ddgs`、`tavily`；后续增加适配器并注册后，修改这一配置及对应服务参数、重启后即可切换。未实现的服务名称明确报错，不静默换用其他服务

`app/tools/web_search.py` 使用 `@tool` 装饰模块顶层的 `async def web_search(query: str)`，将统一搜索能力注册为 LangChain 工具。搜索服务在 `dependencies.py` 创建，通过图的 `with_config` 传入，由工具内的 `get_config()` 读取；模型只提供查询词，不接触服务对象或 Key。LangGraph 和前端只认识 `web_search`，不读取服务商的响应格式。默认配置为 `SEARCH_PROVIDER=ddgs`，依赖中加入 `ddgs`。切回 Tavily 时设置 `SEARCH_PROVIDER=tavily` 并填写 `TAVILY_API_KEY`，Key 仅由后端读取，Tavily 继续复用已有异步 HTTP 客户端

DDGS 的同步搜索在 AnyIO 工作进程中执行，避免阻塞异步接口；停止或超时时终止正在执行该次搜索的工作进程。使用 AnyIO 自带的跨平台进程管理，不自行调用 shell，也不另建常驻搜索服务。单个搜索源的网络等待设置为 10 秒，整次 DDGS 搜索最多等待 15 秒；结果按统一规则校验网页链接、去重、限制条数和摘要长度，空结果、限流、超时及异常数据分别处理

`app/agent/graph.py` 使用 `model.bind_tools()` 告诉模型有哪些工具，使用 LangGraph 自带的 `ToolNode` 执行。流程为 `START → model`；有工具调用则进入 `tools → model`，没有则结束。允许只有工具调用、没有正文的模型回复。达到工具调用上限时关闭本轮后续工具选择，要求给出最终回答

搜索结果是外部参考资料，不作为系统指令。每次最多取五条结果，限制摘要长度，过滤无效链接，控制返回模型的内容量。搜索请求设置独立超时；额度、认证、网络及数据格式错误转换成不含密钥的中文提示

模型发出工具调用前可能输出过渡文字，切换到搜索时清空这段临时正文；最终只保存最后一次模型回答。后端从实际工具结果生成“搜索来源”链接列表附在回答后，避免来源完全依赖模型自行编造。工具调用过程只在本轮页面展示，来源链接作为 Markdown 正文保存，不新增数据库表或字段

### 接口变动

`POST /conversations/{id}/messages/stream` 在现有 SSE 中增加以下事件，请求参数不变。所有事件继续携带本轮 `request_id`

| 事件 | 新增数据 | 页面处理 |
|---|---|---|
| `answer_reset` | 无 | 清空本轮临时正文，保留工具状态 |
| `tool_start` | `call_id`、`tool: web_search`、`query` | 显示正在搜索和查询词 |
| `tool_end` | `call_id`、`tool`、`query`、`status`、`sources`、`error` | 更新该次搜索的结果；`status` 为 `completed` 或 `error`，`sources` 为标题和链接列表，`error` 为失败提示或空值 |

`delta` 用于追加回答正文及后端生成的来源列表，`done.messages` 中的最终正文与已发送内容一致。前端按请求和工具调用编号更新状态，切换会话不影响原会话的搜索。停止或失败时结束“正在搜索”提示，重试时清空本轮临时工具状态

`app/services/streaming.py` 同时读取图的消息片段和节点完成结果：模型节点片段继续转换为 `delta`，模型提出工具调用时发送开始事件，工具节点返回后发送结束事件，最后只保存最终答案。等待搜索时沿用 SSE 心跳和现有断开清理
